## 1. What we are building

**HARNESS is "OpenZeppelin Wizard, but for DeFi."**

OpenZeppelin's Contracts Wizard (wizard.openzeppelin.com) lets a developer tick checkboxes and get
production-shaped Solidity for tokens, NFTs and governance. It has **no DeFi support at all**.
Meanwhile, developers building contracts that integrate with lending protocols (Aave, Morpho,
Compound) repeatedly ship the same well-documented Critical bugs.

HARNESS has **three pillars**:

| # | Pillar | What the user does | What they get |
|---|---|---|---|
| 1 | **Generate** | Ticks checkboxes for an Aave v3 integration | A hardened Solidity contract + a Foundry project |
| 2 | **Audit** | Optionally edits the generated code, or pastes their own | Findings mapped to real historical hacks, each citing a runnable exploit PoC |
| 3 | **Simulate** | Clicks "run scenario" | The contract deployed to a fork of **real mainnet** with **real Aave**, executing a real supply/borrow/flash-loan, with a call trace |

**Scope for v1: Aave v3 only.** Morpho/Compound are roadmap, not build targets.

**One-line pitch:** *Every wizard generates code. HARNESS generates the code, the attacks on it, and
the proof it survives them.*

## 2. Why this is worth building (verified research)

### 2.1 The gap is real
- OZ Wizard's Solidity kinds are exactly: `erc20`, `erc721`, `erc1155`, `stablecoin`,
  `realWorldAsset`, `account`, `governor`, `custom`. **No ERC-4626. No vault. No DeFi.**
- ⭐ OZ's **Stellar** wizard *does* ship a `vault` kind. The Solidity one does not. Best single
  citation that the gap is known and unfilled.
- DuckDuckGo returns literally *"No results found"* for `"aave starter kit" solidity template`.
  No Scaffold-ETH Aave extension exists.

### 2.2 The adjacent markets are already closed — do NOT compete there
- **Aave Kit** (`npm i @aave/react@next`) ships `useSupply()`, `useBorrow()`, `useVaultDeposit()`
  across 14 chains.
- **Morpho SDK** builds slippage-protected viem transactions with `getRequirements()`.
- ⇒ **Never generate frontend/SDK/TypeScript integration code.** That market is owned.
- ⇒ **The on-chain Solidity integration contract is generated by nobody** — and that is precisely
  where every Critical-severity finding in the public audit corpus lives.

### 2.3 The differentiator, in one sentence
Every audit source converges on the same remedy: **fork tests with hostile inputs.** Verbatim from
research: *"That checklist is mechanical and nobody ships it."* Mechanical means generatable.

### 2.4 Naming
⚠️ **"DeFi Wizard" is taken** by an existing startup (ERC20/staking codegen). Do not use it.
Ship as **HARNESS** — you *harness* a protocol, and a *test harness* proves it is safe.

```
│   ├── package.json              #     its own deps, its own lockfile
│   ├── src/types.ts              #     copy of contract/types.ts
│   ├── src/generator/
│   │   ├── aave/flashLoanReceiver.ts
│   │   ├── aave/erc4626Vault.ts
│   │   └── attacks/assembleAttackTests.ts
│   └── src/app/                  #     pages, options panel, CodeMirror, audit UI
│
└── harness-api/                  # ███ AGENT B ONLY ███  standalone Node service

    │   ├── audit.ts              #     rule engine
    │   ├── deploy.ts             #     viem → Tenderly
    │   └── simulate.ts           #     Tenderly scenario runner
    ├── knowledge/findings.json   #     curated audit rules + hack citations
    └── contracts/                #     OZ + Aave sources for solc import resolution
```

**Why two `package.json` files instead of a monorepo:** a shared lockfile is the single most common
way two AI agents deadlock — every `npm i` from one agent dirties the other's tree. Two independent
apps means two installs, two dev servers, two deploys, zero contention. The cost is one duplicated
60-line types file, which is a trade worth making at this timescale.

**Deployment:** `harness-web` → Vercel. `harness-api` → Vercel (separate project), Railway, or
Render. Agent B **must enable CORS** for the web origin.

### 5.2 Stack — all decisions are pre-made, do not re-litigate

| Layer | Pick | Why |
|---|---|---|
| Codegen | `npm i @openzeppelin/wizard` — use its exported `ContractBuilder` + `printContract` | Free OZ-grade formatting, import dedup/sorting, override handling, remappings |
| App | **Next.js App Router on Vercel** | Server routes needed for compile + Tenderly |
| Editor | **CodeMirror 6 + `@replit/codemirror-lang-solidity`** (MIT, 132k wk downloads) | ⚠️ **Monaco has NO Solidity grammar** — you would hand-roll a Monarch tokenizer. Do not use Monaco. |

| Compile | **SERVER-SIDE**: Next route + npm `solc` | ⚠️ Browser solc's import callback is **synchronous** — every OZ/Aave source must be in memory before compiling; the documented workaround is a fetch-and-recompile loop. Do not attempt this at hour 9. |
| Deploy | **viem `deployContract`** onto a **pre-created** Tenderly Virtual Environment | No forge, no Docker, no CI |

### 5.3 ⭐ How to extend OZ Wizard (the single biggest time-saver)

**`@openzeppelin/wizard` v0.10.13 exports `ContractBuilder`, `printContract`, `OptionsError`, and
the `Contract`/`Options` types.** Proof: OZ's own `packages/core/confidential/src/print.ts` and
`packages/ui/src/mcp-apps/confidential/adapter.ts` import exactly these.

**OZ has already built our extension pattern twice.** `@openzeppelin/wizard-uniswap-hooks` and
`@openzeppelin/wizard-confidential` are thin packages that reuse `ContractBuilder` + `printContract`
and add only `additionalCompatibleLibraries: [{ name, path, version, alwaysKeepOzPrefix }]`.
**`core/uniswap-hooks/src/print.ts` is ~17 lines.** Copy that shape exactly.

Internals to know: it is **not** string templates and **not** an AST — it is a small in-memory IR
plus a pretty-printer. `ContractBuilder` accumulates imports / parents / functions / structs /
variables / natspec; `printContract(contract, opts)` emits SPDX → pragma → imports →
`contract X is ...` → body. `erc20.print(opts)` is literally `printContract(buildERC20(opts))`.

Also worth copying: `core/solidity/src/zip-foundry.ts` → `zipFoundry(c, opts)` builds a JSZip
containing `src/X.sol`, `test/X.t.sol`, `script/X.s.sol`, `setup.sh`, `README.md`.

❌ **Do NOT fork the OZ monorepo.** Yarn workspaces + Deno checks + changesets + a Svelte UI +
147 releases of churn ≈ 3 hours burned for zero benefit.

### 5.4 ⚠️ Security requirement (non-negotiable)
**CVE-2026-48054**: OZ Wizard `<0.10.9` interpolated `opts.name` / `opts.uri` straight into
generated Hardhat test TypeScript, enabling injection.

**Every user-controlled value we interpolate into generated Solidity, tests, scripts, or the zip
must be strictly validated and escaped.** Enforce: contract names match `^[A-Za-z_][A-Za-z0-9_]*$`,
addresses match `^0x[a-fA-F0-9]{40}$`, numerics are bounded integers. Reject, do not sanitize.

### 5.5 ⚠️ Licensing
`@openzeppelin/wizard` is **AGPL-3.0-only** (relicensed from MIT ~2 years ago). §13 is a *network*
copyleft: hosting a web app that links it obliges us to offer complete corresponding source under
AGPL. **For a hackathon this is fine** — ship a public repo with an AGPL `LICENSE` file. Flag it
before any commercialization. Generated contracts are unaffected (they carry their own SPDX header).

#### The fixture handshake — this is what actually decouples them

By **hour 1**, each agent commits realistic sample payloads to `fixtures/`, then builds against the
*other agent's fixture* — never against their live service.

- **Agent A publishes** `sample-generated.json` (a real `GeneratedProject`). Agent B compiles and
  audits **that file** all day and never needs A's UI running.
- **Agent B publishes** `sample-compile.json`, `sample-audit.json`, `sample-simulate.json`. Agent A
  renders **those files** all day and never needs B's server running.
- **Agent B also publishes** `attack-snippets.json` by h4 (see §8.2): Solidity test bodies keyed by
  finding ID, using placeholder tokens `{{CONTRACT}}`, `{{POOL}}`, `{{ASSET}}`, `{{ATOKEN}}`.
  Agent A substitutes and stitches; Agent A never has to research an exploit.

If a fixture must change, the publishing agent updates it and says so. That is the only cross-agent
communication required for 10 hours.

## 6. THE SHARED INTERFACE CONTRACT — write this file FIRST, together, in the first 20 minutes

Both agents depend on these types. Agree on them before splitting up, then never change them
without telling the other agent. `packages/generator/src/types.ts`:

```ts
export type Preset = 'aave-v3-flashloan-receiver' | 'aave-v3-erc4626-vault';

export interface GenerateOptions {
  preset: Preset;
  name: string;                  // ^[A-Za-z_][A-Za-z0-9_]*$
  access: 'none' | 'ownable' | 'roles';
  pausable: boolean;
  asset?: `0x${string}`;         // underlying ERC20
  routerAllowlist: boolean;
  claimRewards: boolean;
  sweepEscapeHatch: boolean;
  depositCap?: string;           // decimal string, vault preset only
  feeBps?: number;               // 0..1000, vault preset only
}

export interface GeneratedProject {
  contractName: string;
  contractSource: string;        // src/<Name>.sol
  attackTestSource: string;      // test/<Name>.attack.t.sol
  deployScriptSource: string;    // script/<Name>.s.sol
  remappings: string[];
  appliedFindingIds: string[];   // which knowledge/findings.json rules are mitigated
}

export interface Finding {
  id: string;                    // e.g. 'AAVE-FL-001'
  title: string;
  severity: 'critical' | 'high' | 'medium' | 'low';
  vulnClasses: string[];         // AuditVault slugs, e.g. ['vuln/access-control/missing-auth']
  summary: string;               // one sentence, plain English
  detail: string;                // 2-4 sentences
  incidents: { name: string; loss?: string; url: string; pocFolder?: string }[];
  detect: { kind: 'regex' | 'absence'; pattern: string; appliesTo: Preset[] }[];
  remediation: string;
}

export interface AuditResult {
  findings: (Finding & { status: 'mitigated' | 'triggered'; line?: number })[];
  score: { mitigated: number; triggered: number };
}

export interface CompileResult {
  ok: boolean;
  abi?: unknown[];
  bytecode?: `0x${string}`;
  sizeBytes?: number;
  errors: { severity: string; message: string; line?: number }[];
}

export interface DeployResult { address: `0x${string}`; explorerUrl: string; txHash: string; }

export type Scenario = 'supply-borrow' | 'flashloan-simple' | 'leverage-loop';
export interface SimulateResult {
  ok: boolean;
  scenario: Scenario;
  trace: { depth: number; from: string; to: string; fn: string; value?: string }[];
  balanceChanges: { token: string; delta: string }[];
  explorerUrl?: string;
}
```

**Both agents mock the other side immediately** (Agent A hardcodes a fake `CompileResult`; Agent B
hardcodes a fake `GeneratedProject`) so neither ever blocks on the other.

## 9. Verified technical reference

### 9.1 Minimal correct Aave v3 surface
- **Discovery:** `PoolAddressesProvider.getPool()` / `.getPriceOracle()` — **never hardcode Pool
  addresses**; markets are chain- and provider-specific.
- `supply(asset, amount, onBehalfOf, referralCode)` — approve the **underlying** first;
  `referralCode = 0` (program inactive).
- `withdraw(asset, amount, to) returns (uint256)` — **use the return value**; `type(uint256).max`
  means "everything".
- `borrow(asset, amount, interestRateMode, referralCode, onBehalfOf)` — `interestRateMode` is
  **always 2** (stable is deprecated). `onBehalfOf != msg.sender` requires `approveDelegation` on
  the variableDebtToken.
- `repay(asset, amount, 2, onBehalfOf)` — `type(uint256).max` **only** when repaying your own debt.
- **Reads:** `getUserAccountData(user)` → `(totalCollateralBase, totalDebtBase,
  availableBorrowsBase, currentLiquidationThreshold, ltv, healthFactor)`; `getReserveData`;
  `getConfiguration`; `getReserveAToken`; `getUserEMode`; `FLASHLOAN_PREMIUM_TOTAL`.
- **Flash loan:** prefer `flashLoanSimple(receiver, asset, amount, params, 0)`. The receiver
  implements `IFlashLoanSimpleReceiver.executeOperation` and **approves the Pool for
  `amount + premium` — Aave PULLS, you do not push.** Premium initialized at 0.05%,
  governance-adjustable.
- **L2:** `L2Pool` takes a packed `bytes32 args` built via `L2Encoder`; `flashLoan` and
  `setUserEMode` are **not** compressed and stay on the normal Pool. *(Out of scope for v1.)*
- ⚠️ Aave v4 docs are live (Hub & Spoke, Target-HF liquidations) but **mainnet deployment is
  unverified — target v3.**

### 9.2 Tenderly Virtual Environments
Base URL: `https://api.tenderly.co/api/public/v1/account/{account}/project/{project}`

- `POST /environments` with:
  `network_configs: [{ network_id: "1", block_number, chain_config_overrides.chain_id,
  explorer_config: { enabled: true, verification_visibility: "source" },
  accounts: [{ address, balance }] }]`
  → response `active_instance.vnets[].rpcs` gives **Admin RPC** and **Public RPC**.
- Admin-RPC cheatcodes: `tenderly_setBalance`, `tenderly_setErc20Balance`,
  `tenderly_setStorageAt`, `evm_snapshot` / `evm_revert`, `evm_increaseTime`,
  `eth_sendTransaction` (impersonation).
- Simulate:
  `POST /environments/{env}/instance/{inst}/vnet/{vnet}/transactions/simulate` — supports block and
  state overrides; returns **call trace, state changes, emitted events**.
- It forks **mainnet**, so you get real Aave pools, real liquidity, real oracle prices. Sepolia
  cannot do this.
- **The verified-source public explorer page is our demo artifact.**
- ⚠️ **Create the VE ahead of time and hardcode the RPC. Never create one live on stage.**
- Skip `tenderly/vnet-github-action` — it is a repo-CI story and does not demo.

### 9.3 "Open in Remix" (exact mechanism, from OZ's `ui/src/solidity/remix.ts`)
```
https://remix.ethereum.org/#code=<b64>
```
